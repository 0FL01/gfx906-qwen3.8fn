# Запуск задания в OpenCode

Поместить файлы этого пакета в корень репозитория будущего движка. Если в репозитории уже есть AGENTS.md, совместить правила, не затереть существующую полезную настройку OpenCode. Этот пакет не меняет конфигурацию самого OpenCode.

Подключение к выделенной GPU-машине уже настроено через MCP `mi50-llama-remote`. Использовать его для удалённых команд и переноса исходников; рабочие пути обнаружить в R0.

## Начальное сообщение агенту

```text
Твоя задача: реализовать специализированный inference core на C++20 + HIP для Qwen3.8-Flash-Next на моей выделенной машине с 2×gfx906 по 16 GiB, AVX2 Xeon E5-2698B v3 и 128 GB заявленной DDR3-1600 quad-channel.

Удалённое подключение: настроенный MCP mi50-llama-remote.

Прочитай AGENTS.md, STATE.md, RECON.md и PLAN.md. Затем начинай выполнять R0 и переходи к реализации. Не отвечай только архитектурой или списком рекомендаций. Это длительная автономная разработка: пиши код, пересылай его по SSH, компилируй на GPU-машине, проверяй, измеряй, исправляй и продолжай следующую задачу.

Текущий Git-репозиторий является исходником кода. GPU-машина является местом сборки и исполнения. Используй один цикл переноса исходников, сборки и запуска через mi50-llama-remote. Веса и build остаются на GPU-машине; не пересылай их после каждого изменения.

GPU-машина полностью выделена под задачу. Можно останавливать старый llama-server, менять свои процессы и запуск, ставить нужные зависимости, чистить свои результаты и сборки. Не спрашивай подтверждение рутинных действий. Не ломай SSH, не выкладывай секреты и не занимайся ненужными переустановками работающего стека.

Приоритет: корректный самостоятельный runtime, затем скорость полного запроса. Начни с существующего Q4_0 GGUF без изменения весов. Первые важные участки: AVX2/HIP MoE, QSA с инкрементальным индексатором, нормальный prefill, затем MTP2 с полным откатом GDN/PLE/KV. В конце добавь потоковую конвертацию оригинальных safetensors и исследуй собственный квант отдельным вариантом модели.

KISS/YAGNI/Pareto. Без собственного tensor framework, JIT, систем резервного копирования, sha256sum, универсального multi-backend, большого benchmark-сервиса и бесконечного редактирования планов. Git, несколько тестов, один results.jsonl, короткий STATE.md.

Цифры в плане являются целями, не основаниями подгонять тест. Не скрывай изменение модели, precision, context, sampling или acceptance. Не выкидывай MTP и длинный контекст, чтобы получить красивый результат. Не считай общий контекст обработанным только потому, что выделил KV нужной ёмкости.

После каждого рабочего результата обновляй STATE.md и продолжай ближайшую задачу. При заполнении контекста оставляй точные команды и следующую гипотезу, чтобы продолжение не начинало исследование с нуля.
```

## Ожидаемый первый результат

Не новый дизайн-документ. Нужны проверенный SSH/перенос исходников, обнаруженный рабочий HIP toolchain, вывод device probe для обеих GPU, минимальный реальный kernel test и воспроизведённый короткий baseline. После этого начинается R1.
